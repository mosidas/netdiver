# netdiver MVP roadmap

企画書「9. MVP(最初に完成させる最小範囲)」の範囲を、7 つの作業単位(unit)へ分解した一覧である。各 unit は `docs/specs/<unit>/` を workdir とし、仕様 → タスク分解 → 実装の順に駆動する。

企画書の本体は workspace リポジトリの `4_artifacts/netdiver/issues/01_game-design-doc/game-design-doc.md` にある。本書は企画書の内容を再記述せず、章番号で参照する。作業記録は workspace の `1_issues/netdiver/007-mvp-core-loop/` に置く。

## 前提

- Godot 4.7.1、基準解像度 320x180、stretch mode `viewport`、scale mode `integer`、テクスチャフィルタ Nearest。設定は `project.godot` に反映済み。
- Aseprite CLI から SpriteFrames までのアセットパイプラインを構築済み。構成と手順は `docs/asset-pipeline.md` にある。
- グラフィックは placeholder(単色矩形と簡易なスプライト)で実装する。ドット絵の制作は別の作業で行い、placeholder と差し替える。ゲームロジックを先に完成させ、コアループと解析による能力取得が面白いかを早い段階で確認するため。
- 入力アクション(移動・ジャンプ・主武器・副武器)は未定義であり、`foot-player` で `project.godot` に追加する。
- public リポジトリのため main へ直接プッシュしない。unit ごとに作業ブランチを作り、PR を作成する。マージは人間が行う。

### 1.1. 各 unit の範囲と完了条件

#### 1. `test-harness`

`godot --headless --script` で GDScript のテストを実行するランナーを用意し、テストの置き場・命名・アサーションの書き方を規約として定める。`make test` から実行できるようにし、GitHub Actions のワークフローで PR にチェックが付く状態にする。

完了条件: 意図的に失敗させたテストで非ゼロ終了することを確認できる。`make test` と CI の両方で同じテストが走る。

#### 2. `foot-player`

企画書 5.・6. のプレイヤー挙動を実装する。操作は左右移動・ジャンプ・主武器の射撃・副武器の射撃の 4 つに限る。射撃方向は 8 方向とし、移動の入力方向へ撃ち、入力がなければ向いている方向へ撃つ。主武器は弾数無限の連射、副武器はチャージショット(発射後に一定時間使用不可)。体力制とし、被弾から一定時間が経つと自動回復する。体力 0 でリトライする。動作確認のため、床と壁だけの仮ステージを置く。

完了条件: 仮ステージで 4 操作すべてが動き、体力の減少・自動回復・リトライを確認できる。移動・射撃方向・チャージ・回復の各判定にテストがある。

#### 3. `foot-enemies`

雑魚敵 2 種(突進型・射撃型)と敵弾を実装する。敵の攻撃は企画書 5. の条件(予備動作を目視で識別でき、見てから移動を始めても間に合う / 弾速が徒歩の移動速度で画面内を回避できる範囲に収まる / 同時に対処を要求する攻撃は 2 つまで)を満たす形に限る。プレイヤーの弾による敵の被弾・撃破処理を含む。

完了条件: 2 種の敵を仮ステージに配置でき、撃破と被弾が双方向に成立する。敵の状態遷移と弾速の制約にテストがある。

#### 4. `analysis-ability`

雑魚敵 2 種のうち 1 種を撃破したときに解析が自動で走り、能力が第 3 の武器枠へ加わる処理と、その演出を実装する。干渉は操作を伴わない(企画書 5.)。同時に持てる数の扱いは企画書 13. の暫定(直近に取得した 1 種だけを保持し、新しく取得すると置き換わる)に従う。

完了条件: 対象の敵を撃破すると能力が加わり、第 3 の枠として使える。取得・置き換えの条件にテストがある。

#### 5. `foot-stage-boss`

`TileMapLayer` で 1 本道のステージを 1 つ構成し、`Parallax2D` の多層スクロールで背景を作る。横の進行に縦方向の登りを織り交ぜる(企画書 4.)。ステージ末にボス 1 体を置き、行動パターンを 2〜3 持たせる。ボスの攻撃も企画書 5. の条件に従う。撃破するとポータルゲートが出現する。

完了条件: ステージの入口からボスまで到達でき、ボスを倒すとポータルが出現する。ボスの行動パターン遷移にテストがある。

#### 6. `netspace-run`

企画書 8.・12. のネット空間パートを実装する。敵・障害物・弾に奥行きの値 z を持たせ、毎フレーム z を減らす。画面上の位置は、消失点を原点とする変位に焦点距離を掛けて z で割って求める。表示倍率は焦点距離を z で割り、1 を下限に 1x・2x・3x の整数倍へ丸める。描画は z の大きい順(奥から手前)に行う。当たり判定は、z が自機の前後の一定範囲に入ったときだけ画面上の 2D 位置で行う。奥へ収束するネオンの格子は `CanvasItem` のシェーダで描く。区間の長さは 30〜60 秒とし、失敗時は区間の頭からリトライする。

完了条件: 30〜60 秒の区間を通しでプレイでき、障害物回避と射撃が成立する。投影・倍率の丸め・当たり判定の z 範囲にテストがある。

#### 7. `game-flow`

タイトル画面とリザルトを最小限で作り、シーン遷移を実装する。徒歩ステージ → ボス撃破 → ポータル → ネット空間区間 → 次ステージ入口までを接続し、コアループが 1 周繋がることを確認できる状態にする。

完了条件: タイトルから開始して 1 周を通しでプレイでき、次ステージ入口へ到達する。遷移の条件と状態の引き渡しにテストがある。

## 3. スコープ外

| 項目                                           | 判断理由                                                                                                |
| :--------------------------------------------- | :------------------------------------------------------------------------------------------------------ |
| マルチプレイ                                   | 企画書 10. のスコープ外。MVP はコアループ 1 周の成立を確認する範囲に限る                                 |
| セーブ・進行管理の作り込み                     | 企画書 10. のスコープ外。MVP は 1 周通しのみであり、進行を保存する必要がない                             |
| ストーリー演出の作り込み                       | 企画書 10. のスコープ外。物語は指令の一文と結末の分岐だけを持つ(企画書 3.)                             |
| 結末の分岐                                     | 企画書 10. のスコープ外。月の中枢へ到達する範囲を作ってから着手する                                      |
| 多数のステージ、スキルツリー、装備カスタマイズ | 企画書 10. のスコープ外。MVP の完成後にボリューム化する段階で扱う                                        |
| ドット絵の制作(キャラクター・敵・背景)        | placeholder でゲームロジックを先に完成させる方針のため、別の作業で制作して差し替える                     |
| 飛行型の雑魚敵・ギミック敵                     | 企画書 7. で拡張時の追加と定めている。MVP は雑魚敵 2 種に限る                                            |
| 近接攻撃                                       | 企画書 6. で不採用と定めている(敵へ接近する必要があり、回避行動を持たないため離脱の手段がない)         |
| サウンド(BGM・効果音)                         | 企画書 11. に方向性はあるが、コアループの成立を確認するのに必要ない。ドット絵と同じく後続の作業で制作する |
| GDExtension による実装                         | 企画書 12. で「処理速度が問題になった箇所だけ」と定めている。MVP は型注釈付き GDScript に限る            |

## 4. この文書の扱い

全 unit の完了時に本書は役目を終える。未確定・スコープ外のうち以後も参照する必要がある項目は、恒久情報の配置規約(`.claude/skills/dev-core/references/durable-info.md`)に従って ADR・README へ移す。
